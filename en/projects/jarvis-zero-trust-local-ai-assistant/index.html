🤖 JARVIS: local AI assistant under Zero Trust control

The model proposes, a deterministic gateway decides: policy, containment, strong approval and audit log.

An AI assistant treated as a risky identity: it gets no implicit trust. The LLM (Ollama, local) issues structured action requests; a deterministic policy engine allows them, requires approval or denies them.

A personal project in progress, used on my own workstation. File deletion and Git push are deliberately not implemented.

01Security controls

Closed catalogue
The LLM can only request known actions with a validated schema; everything else is denied by default.
Least privilege
Dedicated standard Windows account, scope limited to one folder and enforced by NTFS ACLs, contained paths.
Strong approval
Any change requires a spoken passphrase, plus a TOTP code at the most sensitive level. Single-use authorisation, bound to the action.
Audit
Append-only log chained with SHA-256, secrets redacted; if logging fails, everything is blocked. Kill switch always visible.

02Status

  • Working: typed or dictated conversation, file read/write within scope, controlled Git operations, reminders, project launching.
  • Inference and transcription 100% local (Ollama, whisper.cpp), with no cloud fallback.
  • About 190 automated tests (node:test) and a self-test run under the dedicated account.
  • The most sensitive level (passphrase + TOTP) is limited to running allow-listed test programs, without a shell; deletion and push are not implemented.
